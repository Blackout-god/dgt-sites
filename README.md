# Dream Group Toys · Inkatoys pilot

Рабочий локальный прототип первой отдельной B2B-витрины. Источник каталога по умолчанию — https://dream-group-toys.com.ua/export_xml_dgt/five_brands.xml. Первоначальный файл XML сохранён без изменений как тестовый пример. Цен, корзины и оплаты нет.

## Быстрый запуск через Docker

Требуется запущенный Docker Desktop в режиме Linux containers.

```powershell
docker compose up --build -d
```

- Витрина: http://localhost:3000/uk/
- Английский интерфейс: http://localhost:3000/en/
- Проверка хаба: http://localhost:8787/health

Первый запуск устанавливает зависимости, скачивает актуальный XML по URL, подготавливает каталог и фото, создаёт локальные D1/R2, импортирует данные и запускает Next.js. Фотографии загружаются со старого сайта только при импорте; браузер обращается к локальной витрине и хабу. При повторном импорте фото проверяются через ETag/Last-Modified, если сервер их предоставляет; неизменённый ответ 304 использует кэш. При отсутствии таких заголовков файл скачивается для сравнения хэша. Недоступный или некорректный фид не заменяется незаметно старым XML из папки.

`.data/originals/` — временные локальные оригиналы перед загрузкой в R2, `apps/storefront/public/media/` — оптимизированные версии для локального сайта. Обе папки исключены из Git. В облачном варианте хранилищем оригиналов будет R2, как предусмотрено ТЗ.

```powershell
docker compose ps
docker compose logs --tail 80 hub web seed
docker compose stop
docker compose start hub web
```

`stop` сохраняет данные. Не используйте `down -v`, если нужно сохранить локальные заявки: эта команда удалит volumes с базой и R2.

Получение свежего XML по URL и повторный импорт (без ручной замены файла):

```powershell
docker compose run --rm prepare
docker compose run --rm seed
docker compose exec web npm run sync:hub
```

`FEED_URL` можно переопределить в корневом `.env`. Только для явного офлайн-режима установите `FEED_FILE=five_brands.xml`. При обычном запуске этот файл не используется как источник. Автоматический запуск по расписанию пока не подключён: обновление выполняется при запуске prepare или указанными выше командами.

Не запускайте одновременно Windows npm и Linux npm в одной папке `node_modules`. Docker использует собственный named volume для Linux-зависимостей.

Dev-сервер использует Webpack с polling в Docker, чтобы изменения файлов из Windows надёжно подхватывались контейнером. Production-сборка использует стандартный Next.js build.

## Запуск без Docker

Node.js 22.12+; команды выполняются из корня проекта:

```powershell
npm ci
npm run setup:local
npm run prepare:data
npm run migrate:local --workspace @dream/hub
npm run dev:hub
```

Во втором терминале:

```powershell
npm run seed:hub
npm run sync:hub
npm run dev
```

## Что реализовано

- Next.js App Router + TypeScript + Tailwind 4, статический экспорт для Cloudflare Pages.
- Отдельный бренд Inkatoys: главная, каталог, 68 карточек товаров, о бренде, партнёрам, контакты, информационная страница о данных и 404.
- Украинский и английский интерфейс с сохранением текущего пути при переключении языка. Названия, описания и характеристики товаров пока украинские; в EN показано пояснение. Автоперевод не имитируется.
- Поиск по названию, артикулу и EAN, фильтры наличия и возраста, сортировка, постепенное раскрытие каталога, пустые состояния.
- Галереи всех 314 фотографий, просмотр увеличенного фото, копирование EAN, скачивание оригинала и ZIP из R2.
- XML по HTTPS URL → общий TypeScript-парсер → локальный снимок → защищённый импорт в D1/R2 → снимок хаба для сборки витрины.
- Upsert по offer id и хэшу, сохранение скрытых товаров, проверка потери более 30% отдельно по бренду, журнал успешных и отклонённых импортов, атомарный D1 batch.
- Очистка HTML и вложенных сущностей, проверка EAN, разбор возраста, сохранение новых param/name/unit. Единицы старых полей неизвестны и не выдумываются: значения сохранены как в XML; на сайте есть пояснение.
- Worker на Hono с локальными D1/R2 через Wrangler. JSON API v1 с ключом, пагинацией и updated_since. В пилоте одна локальная партнёрская API-конфигурация, не полноценное управление партнёрами.
- Форма с выбором товара, сохранением в D1, обязательным согласием, ограничением размера, проверкой origin, honeypot и лимитом запросов. Письма не отправляются. Перед формой это явно указано.
- Локальный шрифт Manrope (OFL), адаптивная вёрстка, клавиатурные фокусы, reduced-motion, метаданные и Schema.org без выдуманных цен.

## Где менять оформление под Figma

```text
apps/storefront/src/config/brand.ts       — бренд, тема, языки, подборки
apps/storefront/src/app/globals.css      — типографика, сетки, стили компонентов
apps/storefront/src/components/          — повторно используемые интерфейсы
apps/storefront/src/app/[locale]/        — композиция страниц
apps/storefront/src/lib/i18n.ts          — тексты интерфейса
packages/catalog/src/index.ts           — модель данных и импорт, без дизайна
apps/hub/src/index.ts                    — API и хранилища, без дизайна
```

При получении Figma можно заменить тему, компоненты и композицию страниц, сохранив модель товаров и API. Текущий логотип — текстовый концепт для примера, не утверждённый брендбук.

Следующий бренд будет отдельным сайтом на своём домене и отдельным Pages-проектом из общей кодовой базы. Сейчас поддержан только Inkatoys: недостаточно просто поменять переменную BRAND, требуется добавить конфигурацию бренда, контент и тему. Товары других брендов в этот сайт не попадут.

## Настройки и секреты

`setup:local` генерирует случайные ADMIN_TOKEN и PARTNER_API_KEY в игнорируемом `apps/hub/.dev.vars`. Не публикуйте этот файл. Скрипты seed/sync читают его без вывода токенов в логи.

- `/internal/*` требует ADMIN_TOKEN и работает только при `LOCAL_DEVELOPMENT=true`.
- `/api/v1/products?brand=INKATOYS&lang=uk&page=1&updated_since=...` — ключ через `X-API-Key`, `Authorization: Bearer ...` или `key` в URL; предпочтителен заголовок.
- `/api/v1/products/{id}` — тот же ключ.
- `/media/originals/{id}/{n}.{ext}` и `/downloads/{id}/photos.zip` — публичные фотографии, как на открытой витрине.
- Порты Docker опубликованы только на loopback, не в локальную сеть.

Хост и порт `localhost:3000` нужно использовать как указано. При изменении адреса витрины обновите `ALLOWED_ORIGINS` в конфигурации хаба и `NEXT_PUBLIC_HUB_URL` в окружении витрины.

В `wrangler.jsonc` стоит placeholder database_id для локального режима. Облачные D1/R2 и backend пока не развёрнуты. Демонстрационная витрина публикуется отдельно, как описано ниже.

## Демонстрация на Cloudflare Pages Free

Опубликована 23.10.2026: [Inkatoys demo](https://inkatoys-demo.pages.dev/uk/). Проект `inkatoys-demo`, production-ветка `main`. Подробности текущей публикации — `.data/pages-demo-deployment.json`.

Без GitHub, через Direct Upload:

```powershell
npm run build:demo
# Путь к готовому каталогу записан в .data/pages-demo-build.json.
npx wrangler pages deploy output/pages-demo/<timestamp> --project-name inkatoys-demo --branch main
```

`build:demo` создаёт отдельную статическую копию с товарами и фотографиями. Поиск, фильтры, галереи и обе локали работают без backend. Форма отключена с пояснением для посетителя; кнопки скачивания ZIP и оригиналов скрыты, поскольку облачный хаб ещё не подключён. Индексация запрещена через robots и X-Robots-Tag. Публикуйте только готовый каталог сборки: исходники, `.data`, `.env` и `.dev.vars` туда не входят.

После изменения каталога или дизайна нужно повторить сборку и загрузку. Автоматического обновления опубликованной демонстрации из XML пока нет.

## Сборка и проверки

```powershell
npm test
npm run typecheck
npm run build
npm run verify:local
# Либо сначала получить текущий снимок из запущенного локального хаба:
npm run build:hub
```

Из Docker:

```powershell
docker compose exec web npm test
docker compose exec web npm run typecheck
# Статическую сборку запускайте отдельно от работающего next dev:
docker compose run --rm --no-deps prepare npm run build
```

Экспорт находится в `apps/storefront/out`. Без подтверждённого домена robots запрещает индексацию, sitemap пустой, canonical/hreflang с выдуманным доменом не генерируются. Перед production задайте `NEXT_PUBLIC_SITE_URL` и пересоберите. Schema.org Product без Offers соответствует B2B-каталогу; право на отдельные Google rich results не обещается.

## Что ещё требуется до production

Это первый локальный срез, а не все этапы исходного ТЗ. Не подключены:

- production-ресурсы D1/R2 и backend в облачном аккаунте заказчика, финальный домен и DNS, staging/production (Pages-демонстрация уже опубликована);
- запуск импорта по cron, фоновые очереди с повторными попытками и уведомлениями, автоматические deploy hooks;
- настоящая админка, Cloudflare Access, редактирование/статусы переводов и бренд-контента;
- машинный перевод, глоссарий и проверенные переводы каталога;
- партнёры с отдельными отзываемыми ключами, rate limiting и журнал выгрузок, XML/CSV/XLSX-экспорты;
- production Turnstile, почтовая доставка с повторными попытками/CRM, финальная политика клиента;
- Cloudflare image transformations, Web Analytics, резервное копирование, мониторинг;
- данные и дизайн остальных четырёх брендов, окончательные макеты и проверка Lighthouse ≥90.

Публичный сбор заявок и локальные административные endpoints блокируются без LOCAL_DEVELOPMENT. Перед запуском production нужно заменить этот локальный механизм на Cloudflare Access и настроенный защищённый процесс импорта, а для заявок — Turnstile и доставку.

Проверено при подготовке пилота: 11 unit/API-тестов, статический экспорт 153 страниц, реальные D1/R2 и содержимое ZIP, блокировка частичного импорта, идемпотентный импорт. В браузере проверены поиск по SKU/EAN, наличие, галерея, Escape, форма с сохранением выбранного товара, мобильное меню и сетка на ширине 390px. Тестовая заявка qa@example.test помечена «Локальна перевірка» и не отправлялась по почте.
